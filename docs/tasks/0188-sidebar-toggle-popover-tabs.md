# 0188 Sidebar toggle, collapsed account menu, tab motion

Executor: Haiku 5.5. Work on branch claude/project-thread-3xqb0b. Three host-app bugs from the owner.

## Bugs and known cause
1. **Collapsed sidebar cannot be expanded.** `App/app/templates/_shell_sidebar.html` has one button `[data-sidebar-collapse]`; `initNavigation()` in `App/app/static/app.js` (~line 826) only calls `setCollapsed(true)`. There is no `[data-sidebar-expand]` element in the v2 shell. Fix: that button toggles (`setCollapsed(!document.body.classList.contains("sidebar-collapsed"))`); keep `aria-expanded` in sync, and update `aria-label` between `a11y.hide_menu` and a show-menu key (add `a11y.show_menu` to both language files next to `a11y.hide_menu`; set via a `data-label-hide`/`data-label-show` attribute pair on the button). Keep it visible and usable in the collapsed rail (the brand column stacks it under the logo).
2. **Collapsed account/Settings menu is clipped.** `.ui-sidebar` in `host2.css` has `overflow-y: auto`, which also clips x, so `.host-account-menu` (220 px wide, from host.css 228) is cut by the 72 px rail. Fix in `host2.css` only: when collapsed (and the 1024-1279 px auto-collapsed range) let the menu escape the rail, e.g. `overflow: visible` on the sidebar there, or position the menu `fixed`. The menu must show whole, labels not truncated, with a visible border, above the content (z-index), and stay inside the viewport at 1280 px and 2000 px, and on short windows.
3. **Tab motion.** On Invoices, "Stay fees" switches instantly but "Invoice settings" (route `/entities`, template `entities.html`) appears to slide. Reproduce it first with Playwright (chromium at /opt/pw-browsers, see test_design_shell_browser.py for how the app is launched): click each tab, sample the main content and tab strip transforms/scrollLeft/opacity every 30 ms for 600 ms, and find what moves (suspects: `skeleton.js`/`.page-skeleton` swap, `.ui-tabs` overflow-x scrolling, a CSS transition or animation on the entities page, `lane-enter`, scroll restoration). Remove the cause so all tabs switch instantly with no sliding, and make any remaining motion on the page collapse under `prefers-reduced-motion: reduce`. Do not remove the skeleton for slow navigations unless it is the cause; if it is, only change its timing/animation so a fast tab switch never shows it. State the cause you found in the report.
