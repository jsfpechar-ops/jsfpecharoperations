## 1. Objective
On PostgreSQL, each scheduled job kind can move, by one env setting, from "APScheduler runs the function" to "APScheduler enqueues a row in `job`; a consumer claims it with `FOR UPDATE SKIP LOCKED` and runs the same function". Retries with backoff, dead after 5 attempts, lease recovery after a crash. Once every kind is on the queue, the `scheduler.lock` file lock is no longer taken, so a second worker (and later the Go worker) can share the work. SQLite and an unset setting behave exactly as today. Plan: [migration-plan-v4](../plans/postgresql/migration-plan-v4.md) step 12, decision D4; R-02, R-18.
## 2. Context
- `App/app/scheduler.py`: `start()` (line 495) takes `DATA_DIR/scheduler.lock` with `_acquire_single_instance_lock()` (line 478), then registers 15 jobs with `max_instances=1, coalesce=True` (lines 511–565): interval `ical`, `submit`, `deadlines`, `mail`, `photo_sweep`, `meta_capi`, `door_codes`, `posthog`, `push`, `guide_import` (minutes from `job_intervals()`, line 74); cron `retention` 03:30, `stay_fee_mail` 07:00, `stripe_sweep` 04:15, `billing` 06:00, `billing_snapshot` 06:15. `billing` is not in `job_intervals()`. Each `_job_*` wrapper catches its own exceptions, logs, raises the `job_failed:<id>` alert and records success; it never raises. `shutdown()` (line 591) waits for running jobs (`wait=True`; compose grace 90 s).
- `App/app/worker.py`: `run()` exits with `EXIT_LOCK_HELD` (3) when `scheduler.start()` returns False; the web role never starts the scheduler.
- `config.DB_BACKEND` (`App/app/config.py:103/107`) is `"postgresql"` or `"sqlite"`; `ENABLE_SCHEDULER` is at line 374.
- Rules: SQL through `db` helpers; never call UbyPort or fetch a feed inside a transaction, so a job never runs inside the claiming transaction: the claim commits a lease, the job runs, a second statement records the result. Timestamps are ISO text from `db.utcnow()`, as in every other table. 0466 removed the global writer lock, so claims from two consumers do not queue behind each other.
- Semantics kept from APScheduler: at most one open job per kind (`max_instances=1` + `coalesce=True`) is a unique partial index; kinds run in parallel with each other as today (consumer `max_instances=4`).
- Local PostgreSQL: [0465 §2](0465-goose-migrations.md#2-context).

## 4. Steps
### Part a
1. `App/migrations_pg/00003_job.sql`:
```sql
-- +goose Up
CREATE TABLE job (
    id         BIGINT GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
    kind       TEXT NOT NULL,
    run_at     TEXT NOT NULL,
    payload    TEXT NOT NULL DEFAULT '{}',
    attempts   BIGINT NOT NULL DEFAULT 0,
    locked_at  TEXT,
    locked_by  TEXT,
    done_at    TEXT,
    dead_at    TEXT,
    error      TEXT,
    created_at TEXT NOT NULL
);
CREATE UNIQUE INDEX job_one_open_per_kind ON job (kind) WHERE done_at IS NULL AND dead_at IS NULL;
CREATE INDEX job_due ON job (run_at, id) WHERE done_at IS NULL AND dead_at IS NULL;
-- +goose Down
DROP TABLE job;
```
   Apply locally with `scripts/pg_schema.py apply`; `check` stays OK (0465 lets PostgreSQL-only tables exist).
2. `App/app/config.py`, below `ENABLE_SCHEDULER` (line 374): `JOB_QUEUE_KINDS = frozenset(k.strip() for k in os.environ.get("UBYHOST_JOB_QUEUE_KINDS", "").split(",") if k.strip())`. Validation is in step 4 (config cannot import scheduler).
3. `App/app/jobqueue.py` (every public function raises `RuntimeError("the job queue needs PostgreSQL")` when `config.DB_BACKEND != "postgresql"`):
   - constants `LEASE_MINUTES = 60`, `MAX_ATTEMPTS = 5`, `BACKOFF_MINUTES = (1, 5, 15, 60)`, `KEEP_DONE_DAYS = 7`, `WORKER_ID = f"{socket.gethostname()}:{os.getpid()}"`.
   - `enqueue(kind: str) -> bool`: `INSERT INTO job (kind, run_at, payload, created_at) VALUES (?, ?, '{}', ?) ON CONFLICT (kind) WHERE done_at IS NULL AND dead_at IS NULL DO NOTHING` with `db.execute`; True when a row was added.
   - `claim() -> Optional[dict]`: in `with db.cursor() as cur:` run
```sql
UPDATE job SET locked_at = ?, locked_by = ?, attempts = attempts + 1
WHERE id = (
    SELECT id FROM job
    WHERE done_at IS NULL AND dead_at IS NULL AND run_at <= ?
      AND (locked_at IS NULL OR locked_at < ?)
    ORDER BY run_at, id
    FOR UPDATE SKIP LOCKED
    LIMIT 1
)
RETURNING id, kind, payload, attempts
```
     with (now, WORKER_ID, now, now minus `LEASE_MINUTES`); return the row as a dict or None. One job per transaction; the transaction ends before the job runs.
   - `finish(job_id)`: `UPDATE job SET done_at = ?, locked_at = NULL, locked_by = NULL, error = NULL WHERE id = ? AND locked_by = ?`.
   - `fail(job, exc, interval_minutes: Optional[int])`: `error = f"{type(exc).__name__}: {exc}"[:300]`; when `job["attempts"] >= MAX_ATTEMPTS`: set `dead_at`, clear the lease, call `scheduler._job_failed(job["kind"])` (imported inside the function); otherwise clear the lease and set `run_at = now + min(BACKOFF_MINUTES[attempts-1 capped at the last], interval_minutes or 60)` minutes. Both updates have `AND locked_by = ?`.
   - `purge()`: `DELETE FROM job WHERE (done_at IS NOT NULL AND done_at < ?) OR (dead_at IS NOT NULL AND dead_at < ?)` with now minus `KEEP_DONE_DAYS`; returns the count.
   - `drain(run: Callable[[str], None], stop: threading.Event, limit: int = 50) -> int`: loop up to `limit`: stop set → return; `job = claim()`; None → return; `run(job["kind"])` in try: success → `finish`, exception → `fail`. Returns the count run.
