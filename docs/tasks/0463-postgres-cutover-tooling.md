## 1. Objective
PostgreSQL 16 runs as a Compose service on the existing Lightsail server (owner decision 2026-10-31: self-hosted, no managed database, no pgBackRest), reached by the app over a Unix socket. One script the owner runs on the server, `deploy/lightsail/scripts/pg-cutover.sh`, with `rehearse` (copy of production data into a throwaway database, verified, dropped), `cutover` (stop writes, backup, transfer, verify, switch `.env`, start, health check; any failure rolls back to SQLite by itself) and `rollback`. Plan: [migration-plan-v4](../plans/postgresql/migration-plan-v4.md) step 8. Owner steps: [owner-steps-cutover](../plans/postgresql/owner-steps-cutover.md). Backups of the new database: 0464.
## 2. Context
`App/scripts/sqlite_to_postgres.py --source <sqlite copy> --report <json> --expect-database <name> [--verify-only]` moves every table in one transaction, refuses a non-empty target, bootstraps the schema itself, and writes per-table row counts and typed hashes to the report; `--verify-only` recomputes them against the live target. The app switches backends by env: `UBYHOST_DATABASE_URL` set and `UBYHOST_DB` unset means PostgreSQL (`App/app/config.py`; both set is a startup error; a socket URL needs no sslmode). Compose reads `deploy/lightsail/.env`. `restore.sh` has the idioms for stopping `worker` then `ubyhost`, one-off containers (`docker compose run --rm --no-deps`) and waiting for `/healthz`; `backup.sh` makes the encrypted snapshot. Litestream keeps replicating the SQLite file until plan step 9. The server is the 8 GB plan; the app container has `mem_limit: 768m`; production is near idle (plan §6).

## 4. Steps
1. Compose service `postgres`: image `postgres:16-alpine` pinned by digest (get it with `TOKEN=$(curl -fsS "https://auth.docker.io/token?service=registry.docker.io&scope=repository:library/postgres:pull" | python3 -c 'import json,sys;print(json.load(sys.stdin)["token"])'); curl -fsSI -H "Authorization: Bearer $TOKEN" -H "Accept: application/vnd.oci.image.index.v1+json, application/vnd.docker.distribution.manifest.list.v2+json" https://registry-1.docker.io/v2/library/postgres/manifests/16-alpine | grep -i docker-content-digest`); env `POSTGRES_USER=ubyhost`, `POSTGRES_DB=ubyhost`, `POSTGRES_HOST_AUTH_METHOD=trust` (no password: the owner must not have to add a secret, and the container never listens on a network); `network_mode: none`; `command: ["postgres", "-c", "listen_addresses=", "-c", "shared_buffers=256MB", "-c", "max_connections=50", "-c", "log_min_duration_statement=1000"]`; `mem_limit: 1g`; `restart: unless-stopped`; healthcheck `pg_isready -U ubyhost -d ubyhost`; no `ports`; volumes `ubyhost-pgdata:/var/lib/postgresql/data` and `ubyhost-pgsock:/var/run/postgresql` (both declared under `volumes:` with `name:` like the others). Mount `ubyhost-pgsock:/var/run/postgresql` into `ubyhost` and `worker` too. Nothing else in the compose file changes; the app keeps running on SQLite because `.env` is untouched.
2. The database URL is constant and holds no secret: `PG_URL='postgresql://ubyhost@/ubyhost?host=/var/run/postgresql'` (the image's `pg_hba.conf` trusts local socket connections; only `ubyhost`, `worker` and the script's one-off containers see the socket). Rehearsal URL: same with `/ubyhost_rehearsal`.
3. `preflight` (run by every command): `postgres` container healthy; a one-off `ubyhost` container connects over the socket and prints `server_version_num` (≥ 160000), `max_connections`, `shared_buffers`, and the target database's table count (must be 0 for `cutover`). Free memory on the host (`free -m`) printed as information.
4. `rehearse`: `./scripts/backup.sh` (fails closed without a recipient: keep that); copy the database with `sqlite3 /data/ubyhost.db ".backup /data/pg-cutover/source.db"` inside the running `ubyhost` container, then `PRAGMA integrity_check` on the copy; `docker compose exec -T postgres psql -U ubyhost -d postgres -c 'CREATE DATABASE ubyhost_rehearsal'`; transfer against the rehearsal URL with `--expect-database ubyhost_rehearsal`, then `--verify-only`; print the per-table table from the report; drop the rehearsal database; delete the copy; keep the report at `/data/pg-cutover/rehearsal-<stamp>.json`. End with the line `REHEARSAL OK`.
5. `cutover`: refuse unless a rehearsal report with status ok is younger than 24 h; `backup.sh`; `docker compose stop worker ubyhost` (downtime starts; Caddy keeps answering); copy and integrity-check as in step 4 through a one-off container; transfer into `ubyhost` (`--expect-database ubyhost`), then `--verify-only`; on any failure: `DROP SCHEMA public CASCADE; CREATE SCHEMA public` on the target, `docker compose up -d ubyhost worker`, health check, exit 1 with the reason (SQLite was never written). On success: copy `.env` to `.env.sqlite-<stamp>`, rewrite `.env` so `UBYHOST_DB` is removed and `UBYHOST_DATABASE_URL=<PG_URL>` added; `up -d ubyhost worker`; wait for `/healthz` like `restore.sh`; `curl` `/login` returns 200; on failure restore `.env` from the copy, `up -d`, health, exit 1. Print the downtime in seconds and where the SQLite file and `.env` copy are. End with `CUTOVER OK`.
6. `rollback`: show the newest `.env.sqlite-<stamp>`, warn in one sentence that rows written to PostgreSQL since the cutover are not carried back, require the word `ROLLBACK` typed, restore `.env`, `up -d ubyhost worker`, health check.
7. Put the `.env` rewrite and restore in two shell functions exposed as `env-switch <env-file> <url>` and `env-restore <env-file> <copy>`; test both in `App/tests/test_pg_cutover_script.py` on temp files (`UBYHOST_DB` gone and the URL present after switch; byte-identical after restore; `bash -n` of the script; `docker-compose.yml` parses as YAML and `postgres` has no `ports` key).
8. Document the three commands in the two tables; nothing else in the docs.
