## 1. Objective
Plan v4 step 17 (G5), fourth slice, rule 1 (filing correctness). G5d ports the outcome write of `reporting.submit_batch` in three slices: **G5d-1 (this brief)** the pure decision (each guest's new values, the batch state, the counts, the guests that ran out of automatic attempts); G5d-2 the database writes; G5d-3 alerts, mail, push, audit and the wiring. Here: no database, no network, nothing calls the Go code, nothing changes in production.

- **Traps:**
  - Python `or` treats `""`, `0` and `None` alike: `guest["submitted_at"] or now`, `guest["receipt_submission_id"] or receipt_submission_id(...)`, `if not previous_submission_id`. Match that in Go.
  - The two branches write **different key sets** (an accept writes `last_errors: None` and always `receipt_submission_id`; a refusal writes `submitted_at` and `receipt_submission_id` only when it becomes `sent`). The key set is part of the contract: a missing key means "leave the column alone".
  - `record_errors` can be shorter than the guest list: a missing entry is `""`.
  - A duplicate for a guest already `sent` counts as neither accepted, failed nor blocked.
  - `Classify` is called with `lang` `"en"`; Python passes `result.header_errors` (a string, maybe `""`).
