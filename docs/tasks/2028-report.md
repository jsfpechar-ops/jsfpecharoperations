# 2028 report — the visual diff: per-stack cookies, two pages fixed

Status: review (22 of 22 cases identical at 390 and 1280; 11 of 11 at 768)

The parity audit compares DOM text and markup, so a page can pass every row and still
not look the same. `App/scripts/go_page_parity_screenshots.py` (brief 1820, repaired by
2021) is the only tool that says so, and it could not compare a signed-in page: it took
one session cookie for both stacks, and Python and Go sign their own sessions, so the
value only ever worked on the stack that issued it and the other side rendered anonymous.

## Files changed

- `App/scripts/go_page_parity_screenshots.py` — `--py-cookie-value` and
  `--go-cookie-value` (also `GO_PAGE_PARITY_PY_COOKIE` / `GO_PAGE_PARITY_GO_COOKIE`);
  `run_case()` takes `py_cookie_value` / `go_cookie_value`. `--cookie-value` still sets
  both, for a bare `/login` comparison.
- `go/internal/web/guest/templates/form_content.tmpl` — `{{define "wrap_class"}}g-checkin-page{{end}}`.
  `guest/base.html` has `{% block wrap_class %}` and only `guest/form.html` fills it, so
  the guest form renders inside `.g-checkin-page` and the CSS grid puts the stay card and
  the check-in steps rail beside the form. Go emitted `<div class="g-wrap ">`: the rail
  was in the DOM (the audit saw its text) and stacked under the form on screen.
- `go/internal/web/public/{catalog_pages.json,pages_data.go,templates/pages/landing.tmpl,pages_golden_test.go}`
  and `App/scripts/public_pages_golden.py` — the landing page prints the receipt's
  check mark with `icon('check', 32)`, which the Jinja macro renders at 32 px with a
  1.75 stroke; the catalog only carried the 14 px art, so the mark was half size and
  twice as thick. The catalog now also carries the paths (`icon_paths`) and `IconSized`
  renders them the way the macro does (stroke 2 up to 16 px, 1.75 above).
- `go/internal/web/public/pages_golden_test.go` — `pagePrints` allows `IconSized`, the way
  it allows `Icon`.
