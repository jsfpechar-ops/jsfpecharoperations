## 1. Objective

Fix the second review of PR #953. The filing guard must fail closed when any `.env` line fails to load. `pg-restore.sh` must restart the app even when `docker compose stop` fails part way. The disaster recovery runbook must say that a failed public health check is expected before Cloudflare moves, put the last steps in a safe order, and say "look only" in the browser check. Two servers filing the same guests with the police is what this step prevents (AGENTS.md rule 1).

## 2. Context

Rules: AGENTS.md rule 1 (filing correctness first), rule 3 (no real `.env`, no secrets), rule 4 (bash and pytest only, no new dependency), rule 8 (never push to `main`). No `App/app/` change.

Decisions taken by the orchestrator (do not change):

- **N1, fail-open `.env`.** `filing-guard.sh` runs `if ! source .env`. Inside an `if` condition bash turns `set -e` off, also inside the sourced file. A failing line in the middle (`UBYHOST_GO_JOB_KINDS = ical,submit` is "command not found"; Compose may still read it as a value) or a line that sets one of the guard's readonly names (`MARKER=x`) is skipped, and the guard can exit 0. Fix: before the real `source`, read `.env` in a strict child shell (`bash -euc`) with the same five guard names made readonly; any failing line exits 3. The child shell's output goes to `/dev/null`: its errors can show `.env` text, and the guard runs inside auto-deploy logs. A good production `.env` already passes this, because `deploy.sh` sources `.env` under `set -euo pipefail` at top level.
- **N2, public health check before DNS moves.** `deploy.sh` checks `${UBYHOST_PUBLIC_BASE_URL}/healthz` through Cloudflare (`public_ok`, ~line 30, called ~line 298). Before Cloudflare points at the new box that request gets the "we're down" Worker (503), so every rebuild deploy prints `The public site does not answer after the restart.` and `Rolling back`, and exits 1. The rollback runs `docker compose up -d --no-build`, so the containers are up with the current `.env`. Docs only: say this once at rebuild step 10, with a local check (the same in-container `/healthz` call `deploy.sh` and `pg-restore.sh` use). Final order: `rm .restored-box`, point Cloudflare (DNS and the Worker route), then turn filing on and run `deploy.sh`, which is the first deploy whose public check can pass.
- **N3.** In `pg-restore.sh`, install the restart trap before `docker compose stop`, not after it. Stamp form otherwise unchanged (`stop worker ubyhost`, `up -d ubyhost worker`).
- **N5.** Rebuild step 15 and the drill browser check: look only, never save while `.restored-box` exists (immediate mode files on save).
- Tests also cover: a declined confirm on `--file` leaves no marker; `--file` with the one-run override writes the marker.

Every change is an exact Before/After pair: the Before text must be found exactly once in that file. If a Before is not found verbatim, STOP (§8). Some pairs are part of one line or one paragraph (no line break shown at their end): replace only that text.

````text
# Brief 1169-cont-2: `if ! source .env` turns set -e off inside .env, so a failing
# line (`UBYHOST_GO_JOB_KINDS = ical,submit`, or one that sets a readonly name
# above) would be skipped and the guard could pass. Read .env first in a strict
# child shell with the same names readonly: any failing line exits 3. Its output
# is dropped, because errors can show .env text and this runs in deploy logs.
if ! bash -euc 'readonly MARKER OVERRIDE CALLER_GO_JOB_KINDS CALLER_JOB_QUEUE_KINDS ASSUME_RESTORED; set -a; . ./.env' >/dev/null 2>&1; then
  echo "ERROR: restored box and a line in ${ROOT}/.env fails (for example \`NAME = value\` with spaces, or a name the guard uses). Find it on the box with: bash -euc 'set -a; . ./.env'" >&2
  exit 3
fi
````
