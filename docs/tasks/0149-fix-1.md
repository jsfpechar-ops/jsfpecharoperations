## 1. Objective

0149 stopped at step 4. Root causes, found by the orchestrator in the current code:

1. **32 px controls.** The Send button and the ⋯ trigger carry `ui-btn-compact` (32 px, `host2.css` line 17). The removed 0079 rule used to lift them to 42. v2 controls are 40 px from 768 up (`--control-h`), 44 below (`--control-h-phone`); tests that still say 42 move to 40 (decision 0134-cont-1, not a weakening). The dashboard still forces 42 through `host-design0123.css`, and the shared-menu test demands dashboard and stays triggers be the same height, so those lines go too.
2. **Rows 81.5 px at 1280.** 0149 step 2 gave every desktop `td` a vertical padding of `--space-1` (8 px per row) and every `.ui-sub` a 4 px top margin. When the lane is tight the stay label wraps to two lines (24 + 24 + 19.5 source + 4 + 8 = 79.5 to 81.5). MASTER 7.4 says a row with one sub line grows to at most 60: padding goes back to `0 var(--row-px)`, the `.ui-sub` margin goes; only the second badge keeps its 4 px (MASTER 7.3 rule 3).
3. **25 px overflow at 1024 (cs).** Between 1024 and 1279 the sidebar is collapsed (`host2.css` line 272) and the lane is about 888 px. Six columns with 16 px padding each side, nowrap dates, nowrap badges and a nowrap actions cell exceed it. In that range cells use `--space-3` padding (saves 48 px).
4. **CI, non-browser (8 tests).** e475024 changed two hooks: `<td class="dashboard-row-task" data-card="badge">` no longer matches the regex `<td class="dashboard-row-task">(.*?)</td>`, and the stays row is now `class="ui-row clickable-row"`, so `'class="clickable-row"' in page.text` is false.

Not a bug: the 1280 screenshot in the 0149 report (`stays-1280-cs.png`) is the old committed file (`md5` equal to `git show HEAD:docs/tasks/0079-evidence/stays-1280-cs.png`): the capture test failed at cs/1024 before writing cs/1280. Desktop actions cell = Send (when present) then ⋯, in one row at the right.
