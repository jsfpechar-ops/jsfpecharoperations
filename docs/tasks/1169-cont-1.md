## 1. Objective

Fix the review findings on brief 1169 (PR #953): `pg-restore.sh --file` must also stop the Go service and restart every service with the current `.env`, must write `.restored-box` only after the guard passed and the restore was confirmed, and the guard must also block on `submit` in the caller's shell, keep its own variables safe from `.env`, and say honestly that only scheduled filing is off. Two servers filing the same guests with the police is the failure this whole step exists to prevent (AGENTS.md rule 1).

## 2. Context

Rules: AGENTS.md rule 1 (filing correctness first), rule 3 (no real `.env`, no secrets), rule 4 (bash and pytest only), rule 8 (never push to `main`). No `App/app/` change.

Decisions taken by the orchestrator (do not change):

- **H1, Go service during the restore.** In the `--file` path, `ubyhost-go` (compose profile `go`) kept running with the old env and could claim a pending `submit` job row from the restored database. Now `--file` also stops `ubyhost-go` when `docker compose config --services` (active profiles, as `deploy.sh` line 242 checks) or `docker compose ps --services` (still running) lists it; with the go profile off nothing extra is stopped. Afterwards it runs plain `docker compose up -d` so every container picks up the current `.env`. The stamp form is unchanged (`stop worker ubyhost`, `up -d ubyhost worker`).
- **H2, marker order.** `pg-restore.sh --file` first runs `filing-guard.sh --assume-restored` (checks as if the marker existed). The marker is written only after the guard passed, the confirm, and the container lookup, just before any container stops. A refused run leaves no marker, so a refused `--file` on the production box no longer blocks later auto-deploys. On the live box with filing on, `--file` is refused: use the stamp form, or prefix the override on that one command and `rm .restored-box` after (docs/LIGHTSAIL.md).
- **M1, immediate mode.** `reporting.submit_stay_if_complete` (App/app/reporting.py ~1145, `automation_mode=immediate`) files from the web process when a guest or host saves; it ignores the scheduler and the job lists. No App change: the guard NOTE and the runbook now say "scheduled filing is off; apartments in immediate mode still file when a guest or host saves", and the runbook keeps Cloudflare on the down page until the marker is removed. No known-issues line: `docs/context/known-issues.md` is at its token cap (lint), and the runbook is the one place this lives (rule 9).
- **M2, shell environment.** Compose interpolation (`UBYHOST_GO_JOB_KINDS: ${UBYHOST_GO_JOB_KINDS:-}` in docker-compose.yml) prefers the shell over `.env`, and `deploy.sh` only overrides the shell for lines present in `.env`. The guard captures both job lists from the caller before `source .env` and also blocks on `submit` there. The runbook says to keep both lines in `.env` with a value without `submit`.
- **L1.** `MARKER`, `OVERRIDE` and the two caller lists are captured before `source .env` and made `readonly`; a `.env` that tries to set them fails to source, and a `.env` that fails to source exits 3.
- **L2.** The docs say: prefix the override on the one command, never `export` it.

````bash
#!/usr/bin/env bash
# Filing guard for a restored box (brief 1169, disaster recovery step 6).
#
# pg-restore.sh --file writes .restored-box next to .env: this box was rebuilt
# from a backup file, and the old server may still be filing the same guests.
# While that marker exists, scheduled filing must stay off: UBYHOST_ENABLE_SCHEDULER=0
# and `submit` in neither UBYHOST_GO_JOB_KINDS nor UBYHOST_JOB_QUEUE_KINDS, in .env
# and in the caller's environment (Compose prefers the shell over .env).
# (With `submit` in neither list the Python worker files guests itself, so the
# lists alone never prove that filing is off.)
# Apartments in immediate mode still file when a guest or host saves: keep the
# site on the "we're down" page until the marker is removed.
# The owner removes the marker once the old server is confirmed off:
# docs/DISASTER_RECOVERY.md, "Two servers never file at once".
#
# Usage (from deploy/lightsail): ./scripts/filing-guard.sh [--assume-restored]
#   --assume-restored: check as if the marker existed (pg-restore.sh --file,
#   before it writes the marker)
#   exit 0: no marker; or marker and filing off; or the one-run override is set
#   exit 3: marker and scheduled filing could run
# One-run override, prefixed on the command, never exported, never in .env:
#   UBYHOST_FILING_GUARD_OVERRIDE=1 ./scripts/deploy.sh
set -euo pipefail

ROOT="$(cd "$(dirname "$0")/.." && pwd)"
cd "${ROOT}"

# Captured before `source .env`, and readonly, so .env cannot change them.
readonly MARKER=".restored-box"
readonly OVERRIDE="${UBYHOST_FILING_GUARD_OVERRIDE:-}"
readonly CALLER_GO_JOB_KINDS="${UBYHOST_GO_JOB_KINDS:-}"
readonly CALLER_JOB_QUEUE_KINDS="${UBYHOST_JOB_QUEUE_KINDS:-}"

case "${1:-}" in
  --assume-restored) ASSUME_RESTORED=1 ;;
  "") ASSUME_RESTORED=0 ;;
  *) echo "usage: $0 [--assume-restored]" >&2; exit 2 ;;
esac
readonly ASSUME_RESTORED

if [ "${ASSUME_RESTORED}" != "1" ] && [ ! -f "${MARKER}" ]; then
  exit 0
fi

if [ ! -f .env ]; then
  echo "ERROR: restored box and no .env in ${ROOT}" >&2
  exit 3
fi
if grep -Eq '^[[:space:]]*(export[[:space:]]+)?UBYHOST_FILING_GUARD_OVERRIDE=' .env; then
  echo "ERROR: UBYHOST_FILING_GUARD_OVERRIDE must not be in .env; prefix it on the command for one run" >&2
  exit 3
fi

# .env is what the containers get (env_file); the caller lists are checked too.
unset UBYHOST_ENABLE_SCHEDULER UBYHOST_GO_JOB_KINDS UBYHOST_JOB_QUEUE_KINDS
set -a
# shellcheck disable=SC1091
if ! source .env; then
  echo "ERROR: restored box and .env in ${ROOT} could not be read" >&2
  exit 3
fi
set +a

has_submit() {
  local list
  list="$(printf '%s' "${1:-}" | tr -d '[:space:]')"
  case ",${list}," in
    *,submit,*) return 0 ;;
  esac
  return 1
}

reasons=()
case "${UBYHOST_ENABLE_SCHEDULER:-1}" in
  0|false|no) ;;
  *) reasons+=("UBYHOST_ENABLE_SCHEDULER is not 0: the Python worker files guests") ;;
esac
if has_submit "${UBYHOST_GO_JOB_KINDS:-}"; then
  reasons+=("submit is in UBYHOST_GO_JOB_KINDS")
fi
if has_submit "${UBYHOST_JOB_QUEUE_KINDS:-}"; then
  reasons+=("submit is in UBYHOST_JOB_QUEUE_KINDS")
fi
if has_submit "${CALLER_GO_JOB_KINDS}"; then
  reasons+=("submit is in UBYHOST_GO_JOB_KINDS in the shell environment (Compose prefers it over .env)")
fi
if has_submit "${CALLER_JOB_QUEUE_KINDS}"; then
  reasons+=("submit is in UBYHOST_JOB_QUEUE_KINDS in the shell environment")
fi

if [ "${#reasons[@]}" -eq 0 ]; then
  echo "NOTE: restored box (${ROOT}/${MARKER}): scheduled filing is off; apartments in immediate mode still file when a guest or host saves. Remove the marker once the old server is confirmed off (docs/DISASTER_RECOVERY.md)." >&2
  exit 0
fi

echo "!!! RESTORED BOX: the old server may still be filing the same guests with the police." >&2
for reason in "${reasons[@]}"; do
  echo "!!!   ${reason}" >&2
done
if [ "${OVERRIDE}" = "1" ]; then
  echo "WARNING: UBYHOST_FILING_GUARD_OVERRIDE=1: continuing with scheduled filing on. Remove ${ROOT}/${MARKER} once the old server is confirmed off." >&2
  exit 0
fi
echo "ERROR: automatic filing stays blocked on a restored box (${ROOT}/${MARKER}). Stop the old server, then follow docs/DISASTER_RECOVERY.md, \"Two servers never file at once\"." >&2
exit 3
````
