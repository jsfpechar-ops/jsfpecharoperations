## 1. Objective
PostgreSQL schema changes after version 33 are goose SQL files in a new directory `App/migrations_pg/`, tracked in goose's own table `goose_db_version`. `App/app/migrations/` stays frozen at `0033_admin_queue_index.sql` and keeps building SQLite exactly as today. The app refuses to start on PostgreSQL when a goose file is not applied. CI proves the goose binary accepts the same files and builds the same schema. Plan: [migration-plan-v4](../plans/postgresql/migration-plan-v4.md) step 10, decision D3 (goose), risk R-14.
Part a (no binary, no network): baseline file, Python reader that applies goose files, startup check, tests, rules. Part b: goose binary in CI, restore of the `test-postgres` job, owner and docs lines. Each part is its own PR and is green on its own.
## 2. Context
- How PostgreSQL gets its schema today: `App/app/db.py:1675 apply_postgresql_schema()` (owner command `App/scripts/pg_schema.py apply --expect-database <name>`) renders the frozen SQLite `SCHEMA`, `ADDED_COLUMNS` and the 32 files 0002–0033 through `db_postgres.render_ddl` (`_postgres_schema_ddl`, db.py:1634) and records them in `schema_migrations`. The transfer `App/scripts/sqlite_to_postgres.py` builds the same schema with `bootstrap_empty_postgresql_schema` (record_history=False) and copies the `schema_migrations` rows from SQLite. The cutover script (0463) runs that transfer; nothing runs `apply` after it.
- Startup on PostgreSQL: `init_db()` (db.py:1590) calls `validate_postgres_schema()` (db.py:1405), which requires `postgres_schema_status()["current"]` (db.py:1266). `current` is false when any table exists that the SQLite baseline does not know (`expected.keys() == actual.keys()` at db.py:1346; the column loop at db.py:1296 also counts an extra table as a column mismatch). A goose table or any new PostgreSQL-only table would therefore stop the app; part a fixes that.
- `expected_schema_version()` is 33; `test_db_postgres.py:250` asserts it.
- Tests: `App/tests/test_db_postgres.py` skips without `UBYHOST_TEST_DATABASE_URL`; its fixture `pg_runtime` (line 146) wipes `public` and calls `apply_postgresql_schema()`. The CI job `test-postgres` that ran it was added in 55ad464 (0460) and dropped again by c935c55 (an unrelated 0461 commit); it is not on main now. Part b restores it.

```
-- +goose Down
-- +goose StatementBegin
DO $$ BEGIN RAISE EXCEPTION 'the baseline is never rolled back'; END $$;
-- +goose StatementEnd
```
   Check it builds the same schema without goose: `sed '/^-- +goose Down/,$d' App/migrations_pg/00001_baseline.sql | psql -h /tmp/pgt/sock -p 55433 -U postgres -d ubyhost_test_goose -v ON_ERROR_STOP=1 -1 -q -f - 2>&1 | tail -3`, then `UBYHOST_DATABASE_URL='postgresql://postgres@/ubyhost_test_goose?host=/tmp/pgt/sock&port=55433' .venv/bin/python scripts/pg_schema.py check --expect-database ubyhost_test_goose 2>&1 | tail -2`. Expect `check OK ... version=33`. Then diff the two dumps: `diff <(pg_dump ...-d ubyhost_test --schema-only --no-owner --no-privileges --no-comments) <(pg_dump ...-d ubyhost_test_goose ...same flags) | head -20`. Expect no output. Drop and recreate `ubyhost_test_goose` after.
4. In `App/app/db.py`, below `BASELINE_VERSION = 1` (line 1493), add `GOOSE_DIR = Path(__file__).resolve().parent.parent / "migrations_pg"` and `GOOSE_TABLE = "goose_db_version"`, then these functions (PostgreSQL only; each raises `RuntimeError` when `config.DB_BACKEND != "postgresql"`):
   - `goose_files() -> List[tuple]`: `(version, name, path)` for `NNNNN_name.sql` files in `GOOSE_DIR`, sorted; `RuntimeError` on a duplicate version or a name not matching `^(\d{5})_[a-z0-9_]+\.sql$`.
   - `_goose_up_statements(text) -> List[str]`: the part between `-- +goose Up` and `-- +goose Down` (or the end); a `StatementBegin`..`StatementEnd` block is one statement; everything else is split with the existing `_statements()` (db.py:1528). Comment-only chunks are dropped.
   - `goose_applied(conn) -> set`: empty set when `to_regclass('public.goose_db_version')` is null; otherwise `SELECT DISTINCT ON (version_id) version_id, is_applied FROM goose_db_version ORDER BY version_id, id DESC` through `conn.execute_native`, keeping versions whose newest row has `is_applied`. Version 0 is ignored.
   - `_goose_ensure_table(conn)`: `CREATE TABLE IF NOT EXISTS goose_db_version (id integer PRIMARY KEY GENERATED BY DEFAULT AS IDENTITY, version_id bigint NOT NULL, is_applied boolean NOT NULL, tstamp timestamp NOT NULL DEFAULT now())` and, when the table is empty, `INSERT INTO goose_db_version (version_id, is_applied) VALUES (0, true)` (what goose itself writes on first use).
   - `goose_pending(conn) -> List[int]`: file versions not in `goose_applied(conn)`.
5. In `apply_postgresql_schema()` (db.py:1675), inside the same transaction, after `_postgres_schema_ddl(...)` and before `COMMIT`: `_goose_ensure_table(conn)`; if 1 is not applied, `INSERT INTO goose_db_version (version_id, is_applied) VALUES (1, true)` (the Python renderer just built version 33, which is what 00001 contains; the SQL of 00001 is never executed by Python); then for every pending version > 1 in order, execute its Up statements with `conn.execute_native` and insert `(version, true)`. Nothing else in the function changes. A failure rolls back everything, as today.
