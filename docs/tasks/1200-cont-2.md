# 1200-cont-2: Stuck-check tests must not depend on machine uptime

## 1. Objective

Two tests in `App/tests/test_job_queue.py` set `jobqueue._last_stuck_check` to `0.0` and expect the next `drain` to run the stuck check. `drain` checks `time.monotonic() - _last_stuck_check >= STUCK_CHECK_SECONDS` (300). `time.monotonic()` counts from boot on Linux, so on a CI runner that booted less than 300 s earlier the check is skipped and both tests fail (CI run 43401843884 on PR #965: `assert [] == [1]`, `assert [1] == [1, 1]`; the same tests passed one push earlier). This fix sets the value to "one window ago" instead. Test-only; no app code changes.

## 2. Context

`App/app/jobqueue.py` lines 208-211:

```python
    global _last_stuck_check
    if time.monotonic() - _last_stuck_check >= STUCK_CHECK_SECONDS:
        _last_stuck_check = time.monotonic()
        watch_stuck()
```

`App/tests/test_job_queue.py` has this line twice (lines 302 and 338):

```python
    monkeypatch.setattr(jobqueue, "_last_stuck_check", 0.0)
```
