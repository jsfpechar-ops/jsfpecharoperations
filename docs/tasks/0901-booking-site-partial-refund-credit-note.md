# 0901: Credit note (dobropis) on a partial refund of a site booking

Status: todo
Depends on: 0818 to 0822 merged (#736) | Base commit: tip of origin/main | Branch: `task/0901-booking-partial-credit-note`

## 1. Objective

Today a PARTIAL refund of a paid site booking (Flexible/Moderate policy after the full-refund date) leaves the host's invoice unchanged and only writes audit `site_invoice_needs_correction` (known issue K-BS01). That is not acceptable: the invoice must be corrected by a document for exactly the refunded amount. A FULL refund already issues a storno (non-payer) or opravný daňový doklad (payer) through `invoices.cancel`; keep that as is.

After this brief a partial refund issues a correction document with one negative line for the refunded amount, numbered from the same series as every other correction, and the guest can open it from the booking page.

## 2. Context

- `App/app/booking_cancel.py` `cancel()`: the partial branch is `elif booking.get("invoice_id"): db.audit("site_invoice_needs_correction", ...)`. The full branch calls `_storno_invoice(booking)`, which wraps `invoices.cancel(...)` in try/except and audits `site_invoice_needs_correction` on failure. Copy that pattern; never let a failed correction undo or block the refund, the mail or the booking status.
- `App/app/invoices.py`: `cancel()` (line ~760) reverses every item through `_draft_from_original(original, items, kind, reason, correction_date, today)` and `_write_issued(draft, actor)`. `kind` is `"corrective"` for VAT payers (`vat_status == "payer"`), `"storno"` otherwise. `vat_parts(quantity, unit_price, rate)` splits gross into base and VAT. An issued document is immutable; corrections are new rows with `corrects_invoice_id`. `cancel()` refuses when a correction already exists (`already_corrected`); a booking is refunded at most once, so one partial correction per booking is the maximum.
- New function `invoices.correct_partial(invoice_id, refund_czk, reason, actor_user_id, *, today) -> int`: same checks as `cancel()` (`not_cancellable`, `reason_required`, `already_corrected`, plus `bad_amount` unless `0 < refund_czk*100 < original total_haler`). Build the draft with `_draft_from_original(original, [], kind, ...)` then replace `items` by ONE item: `kind` of the original stay item, description `reason`-independent fixed text passed in by the caller (CS key `site_booking.invoice.partial_item`, EN too), `quantity` 1, `unit` as the original stay item, `vat_rate` of the original first item, gross = `-refund_czk*100` haléř; for payers split base/VAT with the original rate (base = round(gross / (1 + rate/100)), VAT = gross - base; use the project helper, do not invent rounding), for non-payers base and VAT are `None` like the original lines. Set `total_haler` (and base/vat totals for payers) to the same negatives. Audit `invoice_corrected` with `partial=1`. Use `kind="corrective"` for payers and `"storno"` for non-payers (no new kind, no migration).
- PDF heading: find how the PDF/view labels kind `storno` and `corrective` (grep `corrects_number` and the invoice PDF template). If the non-payer storno heading reads as a full cancellation ("Storno faktury"), show "Dobropis" when the correction total is smaller in absolute value than the original total, in both languages; payers keep "Opravný daňový doklad". Keep the change to the label logic, no layout change.
- Guest access: `App/app/routes/property_page.py` has `/p/{slug}/b/{booking_id}/{token}/invoice.pdf` (HMAC `booking_site.token_ok`); add `/p/{slug}/b/{booking_id}/{token}/correction.pdf` the same way, serving the PDF of the invoice whose `corrects_invoice_id` equals the booking's `invoice_id` (404 if none). On `booking_manage.html` / `App/app/booking_manage.py`, when a correction exists, show a second button "Opravný doklad (PDF)" / "Credit note (PDF)" next to "Faktura (PDF)" using the same button class, same 44 px rule.
- i18n: new keys in BOTH language blocks of `App/app/host_i18n.py`: `site_booking.invoice.partial_item` (CS "Vrácení části ubytování podle storno podmínek", EN "Partial refund of accommodation under the cancellation policy"), `bk.btn.correction` (CS "Opravný doklad (PDF)", EN "Credit note (PDF)"). `_flash()` keys stay string literals.
- Rules: SQL only through `db` helpers; no migration; no new dependency; a template change needs the browser test below; copy: no sentence the button already says.
