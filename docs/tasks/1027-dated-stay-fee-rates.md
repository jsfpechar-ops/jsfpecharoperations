## 1. Objective

Owner-approved from Czech law research: the per-night stay-fee rate carries an effective-from date and each counted night is priced at the rate in force on that night. A sealed (reported) period is never re-priced. Today `apartment.stay_fee_rate_czk` is one number applied to a whole period.

Design (decided; do not redesign):
- New table `stay_fee_rate (apartment_id, rate_czk, effective_from)`, append-mostly. `apartment.stay_fee_rate_czk` stays as the current rate (still drives `is_active`, the editor, the booking site). It is NOT removed.
- Backfill: every apartment with a rate above 0 gets one row effective `2000-01-01`. No history rows for an apartment means "flat column rate" (so totals are identical to today).
- The price of a counted night `d` is the rate of the latest row with `effective_from <= d`. `d` is the loop variable of `guest_period` (days start+1 .. end), the same day that is counted today.
- Rows may only be added with `effective_from >= today` (decrees are not retroactive). With the existing rule that a period is sealed only when complete (`report_issues` calls `period_complete`), a sealed period can never be re-priced by a later rate row.
- A period with two rates keeps ONE sealed `rate_czk` column (the rate on the period's last day, informational) plus the true per-rate nights in the sealed payload; the PDF facility row is split into one row per rate so `nights x rate == amount` still holds.
- Aggregate bed-day adjustments (`_apply_adjustments`) are priced at the period's last-day rate. Owner may veto: see Questions.

```sql
-- Brief 1027: dated stay-fee rates. Host configuration only, no personal data.
-- A night is priced at the rate with the latest effective_from on or before it.
CREATE TABLE IF NOT EXISTS stay_fee_rate (
    id             INTEGER PRIMARY KEY AUTOINCREMENT,
    apartment_id   INTEGER NOT NULL REFERENCES apartment(id) ON DELETE CASCADE,
    rate_czk       INTEGER NOT NULL CHECK (rate_czk >= 0),
    effective_from TEXT NOT NULL,
    created_at     TEXT NOT NULL,
    UNIQUE (apartment_id, effective_from)
);
CREATE INDEX IF NOT EXISTS idx_stay_fee_rate_apartment ON stay_fee_rate (apartment_id, effective_from);
INSERT INTO stay_fee_rate (apartment_id, rate_czk, effective_from, created_at)
SELECT id, stay_fee_rate_czk, '2000-01-01', '2026-11-08T00:00:00+00:00'
FROM apartment WHERE stay_fee_rate_czk > 0
ON CONFLICT (apartment_id, effective_from) DO NOTHING;
```
